## 2. 频道固化：从「名字」到「实体」

### 2.1 三层模型

```
频道目录 channel_registry        长期存在，人工确认过的身份
  └ 频道槽位 cctv-1              稳定 id + 正式名 + 别名 + 分组 + 组内序号
      └ 源档案 channel_source    一条 URL 的归属与人工干预
          └ 健康记录              沿用 channel_speed_map（每 URL 一条）
```

存储沿用 KV（与现有 `channel_speed_map` 同构），单 key 超 5MB 再迁 SQLite 表。

| KV key | 内容 |
|---|---|
| `live_channel_registry` | `{ id, name, group, order, aliases[], enabled, createdAt }` |
| `live_channel_order` | 已有：组内顺序 + 移出规则 |
| `live_source_overrides` | 人工干预：`{ [url]: { pin?, ban?, trimmedAt? } }` |
| `channel_speed_map` | 已有：每 URL 的健康记录（字段见 §3.1） |

### 2.2 id 规则与初始化（补：这是原设计缺的一块）

**id 形态**：`<类型>-<标识>`，只用小写字母、数字、连字符，一旦分配不再变：

| 类型 | 规则 | 例 |
|---|---|---|
| 央视 | `cctv-<数字>`，`+` 变体为 `cctv-<数字>plus`，4K/8K 为 `cctv-<数字>4k` | `cctv-5`, `cctv-5plus` |
| 卫视 | `sat-<省/品牌拼音>` | `sat-hunan`, `sat-dragon` |
| 地方 | `local-<省拼音>-<城市拼音>` | `local-guangdong-shenzhen` |
| 其他 | `ch-<归一化名字的哈希前 8 位>` | `ch-a1b2c3d4` |

**首次初始化**：第一次跑固化流程时，用当前输出（1166 个频道）批量写入 registry：
按上表规则生成 id；同一 id 出现多个写法时，取出现次数最多的作为 `name`，其余进 `aliases`。
初始化是**一次性动作**，写入后加 `initializedAt` 标记，不重复执行。

**后续变更**：
- 频道改名 → 只更新 `name`，id 不变，旧名进 `aliases`（历史因此不丢）；
- 两个槽位合并 → 保留 id 较小者，另一个作为别名并入，源全部迁移；
- 槽位删除 → 仅置 `enabled: false`，不物理删除（便于回滚）。

### 2.3 归入规则（一次性知识）

```
① channel_id / 正式名完全匹配   → 归入
② 别名表命中                   → 归入
③ 规则归一（CCTV 编号/繁简/后缀）→ 归入，进待确认
④ 编辑距离模糊匹配             → 归入，标低置信
⑤ 全不中                       → 未识别队列
```

未识别队列在「频道」页顶部显示为待办，人工确认一次即写入别名表，**以后不再判断**。
逃生口：新频道 7 天未被确认 → 自动建槽，避免新台被静默吞掉。

> 规模参考：当前 1166 个频道，按 5% 未识别估算约 60 条待办；源每周新增预计 10~30 条。

## 3. 源健康：字段、分级重测、打分

### 3.1 健康字段（直接采用朋友分支的定义，不另造）

| 字段 | 含义 | 来源 |
|---|---|---|
| `kind` / `speedMs` / `probedAt` | 结论、延迟、测于何时 | 已有 |
| `stage` / `ruleVer` / `note` | 判定深度、规则版本、失败原因文案 | 已有（我方） |
| `lastOkAt` | 最近一次成功时间 | **采用他的定义** |
| `consecutiveFails` / `firstFailAt` | 连续失败次数 / 本轮连续失败起点 | **采用他的定义** |
| `lastFailReason` | 最近失败原因（永久 / 长期 / 短期三分） | **采用他的定义** |
| `okCount` / `failCount` | 累计成功 / 失败次数 | **新增** |
| `history` | 最近 12 轮结果位图（`"1111010"`，1 成功 0 失败） | **新增** |

体积估算：16483 条 × 约 60 字节 ≈ **1MB**，KV 可承受。

> 迁移：现有 `fails` → `consecutiveFails`，读取时兼容旧字段；`history` 从空开始累积。

### 3.2 分级重测（采用他的 `shouldProbeEntry`，改一处）

| 条目状态 | 重测间隔 | 说明 |
|---|---|---|
| 从没测过 | 立即 | |
| 成功 | 6 小时 | 我方 TTL |
| 短期失败（网络/超时/5xx） | 24 小时 | 他的 `CHANNEL_FAIL_RETRY_MS` |
| 长期失败（≥3 次且满 7 天） | 7 天 | 他的 `CHANNEL_LONG_TERM_*` |
| 永久失败（404/410/DNS 不存在） | **7 天**（改） | 他原本永不重测；加一次周级回测，避免域名复活后永不发现 |

### 3.3 打分与排序

```
availability = okCount / (okCount + failCount)        # 累计，避免单轮抖动主导
score        = 0.55·availability + 0.30·speedScore + 0.15·stabilityScore
speedScore   = 1 - min(1, p50 / 3000ms)
stabilityScore = history 里最近 6 位的成功比例
```

- **分桶**：先按 availability 分三桶（≥0.9 / 0.6~0.9 / <0.6），桶内按 score 降序；
- **隔离**：`consecutiveFails ≥ 2` 且最近一次为分片失败 → 不参与优先排序，仍保留在列表；
- **去相关**：前 3 条仍保证不同 host；
- **丢包**：HTTP 层测不到 ICMP 丢包，用「分片成功率 + RTT 抖动」作为代理指标，界面文案不写"丢包率"。

## 4. 探测的 host 限流（补：原设计缺的一块）

现状：单域名挂 487 条（`45.192.97.170`），我们以并发 100 去打，测出的"快"和"死"都有自己造成的成分。

```
全局并发 100（不变）
  └ 同 host 并发 ≤ 4（可配 CHANNEL_PROBE_PER_HOST）
      └ 超出的排队，先进先出
```

实现：`runWithConcurrency` 增加一个按 host 的计数表，取到 URL 解析 host，若该 host 在跑数已达上限则等待；
探测结束释放。无新依赖。

```

│ [一键选优]  [保存排序]  [恢复默认]      未识别 12 条 →        │

│ 卫视     44  │ 2 CCTV2    210ms ◐  │ 1 南风   120.76… 18ms │
│ 境内地方 281 │ 3 CCTV3    隔离 ○   │ 2 游魂   39.165… 23ms │
└──────────────┴─────────────────────┴───────────────────────┘
源操作：[置顶] [禁用] [删除] [仅保留该域名 1 条]
```

- 手动排序：复用现有拖动，写 `live_channel_order`；
- 删除源：写死源黑名单（可回滚）；
- 一键选优：按 score 裁到 top N，保留 `pin`/`ban`，裁剪记录写 `trimmedAt` 可还原；
- 「为什么排第一」：展开显示 availability / p50 / stability 三项。

**top N 定 6**，依据：当前 1166 台中 792 台只有 1 条源（68%），超过 6 条源的仅 161 台；
保留 top6 后源数 4837 → 2179（-55%），砍掉的全是冗余，且单台可覆盖。

## 7. 分阶段落地

| 阶段 | 内容 | 验收 |
|---|---|---|
| **P1** | 输出前复核首位源（每台只测第 1，必要时第 2） | 首位可播率 73% → ≥90%；增量耗时 < 2 分钟 |
| **P1.5** | 健康字段对齐（lastOkAt/consecutiveFails/history/okCount）+ host 限流 | 历史可算可用率；单 IP 不再被并发打崩 |
| **P2** | 打分与分桶排序、域名聚合接口 | 排序不被单轮抖动带偏；域名视图可查 |
| **P3** | 频道目录：registry + id 初始化 + 别名表 + 未识别队列 | 同一台多写法归入同一 id |
| **P4** | 「频道」菜单：迁入排序 + 源管理（置顶/禁用/删除/一键选优） | 全部操作在 UI 完成且可回滚 |
| **P5** | 「源健康」菜单顶替 MacCMS | 菜单与路由不冲突，点播不受影响 |

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| 固化后新频道进不来 | 未识别队列 + 7 天自动建槽 |
| 一键选优误删好源 | 裁剪记录可还原；删除只进黑名单 |
| KV 单 key 过大 | 超 5MB 迁 SQLite 表，接口不变 |
| 永久失败永不恢复 | 改为 7 天回测一次 |
| 复核首位增加耗时 | 只测每台第 1（必要时第 2），并发 100 + host 限流 |
| MacCMS 封存影响点播 | 只撤 UI 入口，路由与数据保留 |
