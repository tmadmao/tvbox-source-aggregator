## 1. 现状（2.2.0 · 自建分支 · 2026-11-11）

> 想看「做到哪了、还剩什么」，直接跳 §2 进度看板。本节只描述系统长什么样。

- **工程**：TypeScript + esbuild 单文件打包（`dist/server.js`）；Node 22 / better-sqlite3；`npm run build:node`
- **部署**：绿联 NAS Docker，容器 `tvbox-aggregator`，端口 5678，数据 `data/tvbox.db`；
  **镜像构建期打包 `dist` 并写入 commit**（`tvbox-aggregator:<sha>` + `:local`），容器只挂 `data`，
  重建不会退回旧代码；`dev/nas-update.sh` 在 NAS 上构建镜像 → 重建容器 → 校验 `/version`（改代码走缓存约 60 秒）
- **对外入口**：
  - 局域网 `http://192.168.5.18:5678/live.txt`（302 → `/live-config`，HTTP 缓存 5 分钟）
  - 公网 `http://iptv.new.tg/live.txt`（聚合完成后经 FTP 覆盖上传 `/Web/live.txt`）
- **调度**：聚合 `0 5 * * *`（容器 `TZ=CST-8` → **每天 05:00 北京时间**，不是 UTC）；
  测速并入聚合（KV `channel_probe_inline`），独立的测速 cron 仅在 inline 关闭时生效；
  **执行历史**记触发方式/开始/结束/状态/耗时/产出，保留 7 天（`run_history`），
  进程被杀留下的悬空记录下次启动自动收尾为「进程中断」；
  失败 / 超时 / 超过 26 小时没成功 → 后台标红 + 可选 Webhook / Telegram 推送（`alert_config`），
  每天 06:30 与启动后 30 秒各做一次漏跑自检
- **直播链路**：手动直播源 22 个（配置源自带 lives 默认不采用：会掺入数万条音乐/歌单条目）
  → 下载解析（内容类型闸、单源上限 3 万条、格式识别按行首）
  → 频道归并（`$源名` 剥离、央视编号归一、繁简、后缀剥离）
  → 分组收敛到标准组（央视/卫视/境内地方/境内专题/港澳台/韩国/日本/体育赛事/少儿动画/纪录科教/国际新闻/其他海外/其他）
  → 购物/推广频道过滤（17 个关键词）
  → 组内多源按测速排序（可用 → 未测 → 失败 → 死链）+ 域名去相关（前 3 条不同 host）
  → **健康分参与排序**（先看 tier 0/1/2 档位，再看 score，差距小才比延迟）
  → 死源台账过滤（KV `live_dead_urls`，v2 格式：`[url, state, since, probedAt]`）。
     **台账只增不删**：判死的源留档，下次从外部源再采集到同一地址可直接查档案；
     **受保护域名永不入库并自动回捞**；输出只过滤 `state≠0` 的条目
  → **域名台账再收一层**（KV `live_host_state`）：全死域名抽 3 条周/月复验，
     判死域名名下源整片不输出；部分活域名（实测 63 个）不碰，仍逐条判
  → **付费 / 海外频道排除**（合并后立即生效）：央视数字付费频道（风云/兵器/第一剧场…）
     与 港澳台/台湾/韩国/日本/国际新闻/其他海外 整组删除；**CCTV5+ 例外保留**。
     名单与开关存 KV `live_curation_rules`，后台可改、可恢复
  → **分级源质量保障**（`channel-tier` + `source-guarantee`，Step 6.6c）：
     按 **央视 6 / 卫视 5 / 重点地方台 2** 的「保底可播条数」重排每台源；
     可播 = 本轮探测过 + 分片验证 + 延迟 ≤2.5 秒（客户端 5 秒超时的一半）+ 健康档位非隔离；
     死链与单次失败不再占前排位置，前排优先不同域名；
     不够配额时从**完整源池**继续实测补位（央视最多翻 18 条、卫视 14、地方 8），
     补不到记入缺口报表 `live_quality_gap`，只列央视/卫视/有 2 条以上候选的地方台
  → **源质量守夜**（`quality-guard`，每小时 :20）：重点台头部源超过 1 小时未验或有缺口 →
     立刻重验；缺口从完整源池补，池子不够就重新下载直播源列表找新地址；
     有改善才发布（KV + FTP），质量只升不降；连续 3 轮「央视/卫视可播 ≤1」才告警
  → **重点频道编排**（`channel-curation`）：央视 / 卫视 / 境内地方 三组按台号与地域重排，
     同名异写合并、错组频道归位、伪 CCTV 清出，南京地方台固定置顶境内地方
- **频道编排规则**（`src/core/channel-curation.ts`，规则存 KV `live_curation_rules`）：
  - 央视：CCTV1→17 台号顺序，5+ 跟 5，4K/8K 单列其后，CCTV+/CCTV-NEWS/CGTN/数字付费频道依次收尾
  - 卫视：江苏（本地）→ 湖南/浙江/东方/北京 → 其余省级 → 大湾区/南方/厦门/海峡 → 少数民族与专业卫视
  - 境内地方：南京新闻综合 → 南京十八频道 → 南京教科 → 南京文旅纪录 → 南京少儿 → 南京影视 → 江苏各市县 → 上海/浙江/广东…
  - **台序、每台保留条数、各档保底条数后台可改，保存即生效，改卫视顺序不用发版**
  - 置顶 / 禁用走 KV `live_channel_overrides`，禁用只从输出移除、后台仍可见可撤销
- **测速**：频道级、多采样取中位数、并发 100、单轮预算 20 分钟、每 300 条增量落盘；
  **测量在合并之前**（用上一轮频道树先测速，合并只下载一遍）；
  **L2 分片复验**：列表可达后再拉 2~8KB 分片确认真在出数据（4 秒独立超时），
  播放列表按内容识别，不只看 `.m3u8` 扩展名；
  **缓存按规则版本增量复验**：条目带 `ruleVer`，改判定规则时只让旧条目各自重测一次；
  **分级回测**：成功源 6 小时；进了台账的死源按「可疑 7 天 / 判死 30 天」回测；
  **待测队列按频道档位排序**（央视 → 卫视 → 重点地方台 → 其他），预算紧时先保重点台的本轮结论；
  重点台的源不受「域名未到复验时间整域跳过」限制
- **站点链路**：配置源 44 个 + MacCMS；站点验活（深/浅）→ 不可达剔除（删除 / 保留链接二选一）
  → 相似名去重 → 名称推广词清洗；站点健康历史 `site_health_map`
- **管理后台**：二级菜单 源 / **源健康** / 直播 / 搜索 / **频道** / CLOUD / 设置 / 日志
  （MacCMS 入口已撤下，`panelMaccms` 与 `/admin/maccms*` 路由保留封存）；
  直播页保留直播源、频道测速、分组归并、频道过滤、FTP 发布；
  频道页：频道表（id / 源数 / 首位延迟 / 健康徽章 / 置顶 / 禁用）+ 源明细（可删）+ 一键选优
  + **源质量保障**（各档达标率 / 缺口表 / 补测开关）+ **编排规则编辑**（台序 / 保留条数 / 各档保底）
  + 未识别频道「归入目标频道 id」+ 原有拖动排序（央视/卫视/境内地方 改由编排接管）；
  源健康页：概览 / 按域名 / 失败原因；`/status` 监控页不变；
  日志页：**调度执行历史**（最近 7 天逐日 ✓/✕ + 明细表）+ **告警通道配置**（Webhook / Telegram）
- **产出**：8 个分组 / **659 个频道** / 1590 条源 / 122 KB（`live.txt`）；
  付费台、海外台、4K/8K 已全部删除，**CCTV5+ 例外保留（8 条源，43~379ms）**；
  全死频道已默认隐藏；**央视 / 卫视 / 地方台输出里 0 条死链**（旧版是「1 活 + 7 死」塞满 8 条），
  每台留下的每一条都是本轮探测可播的源
- **可播率的正确读法**：`首位即死数 == 全死数` 才说明排序没白排
  （曾经出现「首位死 525 / 全死 525」但其中一个频道在第 4 位藏着活源，是合并同名时没重排序导致的）
- **质量保障的读法**：`/admin/quality-gap` 里 `coverage` 是「达到保底条数的台 / 参与保障的台」，
  `gaps` 才是真正需要补源的台（央视/卫视必列，地方台只列有 2 条以上候选的）
- **已知问题**：
  1. **卫视尾部与江苏部分地方台只有 1~2 条保底**：大湾区/南方/海峡/安多/山东教育等
     5 台缺 2~3 条，江苏几个地方台 1/2；属源覆盖不足，守夜每小时自动补测并保留缺口报表，
     不需要人手动维护；央视 18 台（1~17 + CCTV5+）全部达标
  2. **死链判定约 23% 是过期结论**：死链按周/月回测，误判最长要等一周才纠正。
     实测把 525 个「全死」频道强制重测后 144 个复活（27%）
  3. `dev/askpass.sh` 存 NAS 明文密码；已 gitignore，但仍建议换 SSH 密钥
  4. 后台「对外访问地址」存的是 `http://iptv.new.tg`（未带 `/live.txt`），仅展示用
  5. 告警通道默认关闭，需在「日志 → 失败告警」里填 Webhook 或 Telegram 才会主动推送

## 4. 明确定不做

- **不换基座**：不把朋友的分支作为主干。他的 UI 是 932 行独立后台 + 独立路由 + 独立快照，
  与「一套现有 UI 框架」的目标冲突
- **不搬规则引擎**：`live-group-rules` 走的是「写正则让源适配规则」，我们走「频道是实体、源挂上去」，
  两条路；只取其中与具体业务无关的纯函数（如省份识别）
- **不向上游提交**：上游分支在开发 `fix/parser-and-source-cache`，与我们的改动冲突；
  所有提交只进 `tmadmao/tvbox-source-aggregator`
- **不做 ZIP 源 / GitHub 镜像归组**：当前源里没有这类需求，搬来就是死代码
